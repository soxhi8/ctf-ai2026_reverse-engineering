The exploitation technique you would use to bypass NX is **ROP (Return-Oriented Programming)**.

Because NX (No-Execute) prevents you from executing code directly on the stack, you cannot inject and run your own custom shellcode. Instead, with ROP, you leverage "gadgets"—small, existing sequences of machine instructions already present in the binary or its linked libraries—to stitch together the execution flow you desire (such as calling `system()` with the argument `"cat flag.txt"`).

In this specific challenge, however, because you have a `win()` function already defined in the binary that performs this task, the simplest application of this principle is to **overwrite the return address on the stack** to point directly to the `win()` function. This is effectively a direct jump to existing, executable code, which is the most basic form of code-reuse exploitation.
