### The vulnerability in vuln.c


c
```c
void vuln(){
        char buffer[0x15] = {0};
        fprintf(stdout, "\nEnter payload: ");
        fgets(buffer, 0x90, stdin);
}
```


- `buffer` is `0x15` = **21 bytes**.
- `fgets(buffer, 0x90, stdin)` allows up to `0x90` = **144 bytes** to be read into it.
- This is a classic **stack buffer overflow**: `fgets` is told the buffer is 144 bytes when it's really only 21, so up to 123 extra bytes get written past the end of `buffer`, overwriting adjacent stack memory (saved registers, saved RBP, and eventually the **return address**).


### The general exploitation idea

2. **Overwrite the return address** with the address of `win()`, which calls `system("cat flag.txt")`.

  - Find `win()`'s address with `objdump -d vuln` or `nm vuln` (if not stripped) — look for `win`'s address, e.g. `0x401196` or similar.

4. Send this payload to the running process, and it should jump to `win()` and print the flag.

## Claude

Based on the checks:


- **Type: EXEC** → **No PIE** (fixed addresses, not ASLR-randomized)
- **GNU_STACK: RW** (no `E`) → **NX enabled** (stack is not executable)
- **GNU_RELRO** present → **Partial/Full RELRO** enabled
- No `__stack_chk_fail` symbol found → **No stack canary**


So the notable protection enabled here is **NX (No-eXecute)** — the stack is not executable, meaning you can't just inject and run shellcode directly on the stack; you'd need to use a **return-to-function** (ret2win) technique like jumping to `win()`, which fits perfectly with what this binary is set up for. There's also **RELRO**, but **no PIE** and **no stack canary**, which is what makes the straightforward ret2win overflow (overwrite return address with `win()`'s address) work cleanly.

## Claude

**ROP (Return-Oriented Programming)** — since NX prevents executing injected shellcode on the stack, an attacker instead chains together existing executable code already in the binary (like calling `win()` directly, or building a ROP chain from existing functions/gadgets) to achieve code execution without needing to run new code on the stack. In this specific binary, since `win()` already exists and calls `system("cat flag.txt")`, the simplest form of this is a **ret2win** — overwriting the return address to jump straight to `win()`.
